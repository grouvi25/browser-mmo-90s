# Apeha → Kooperativ: план адаптации боя и снаряжения

Дата: 2026-08-13

Статус: продуктовый план, **не разрешение на реализацию**.

Связанные материалы:

- `docs/research/APEHA_BATTLE_EQUIPMENT_VISUAL_RECON.md`
- `docs/research/GANJAWARS_APEHA_SYSTEMS_RESEARCH.md`
- `docs/STAGE2_STAGE3_HANDOFF.md`

## 1. Главный принцип

Мы не переносим Apeha как набор старых механик. Мы берем ее причинно-следственную структуру:

- игрок понимает, **кого** выбирает;
- понимает, **куда** бьет и **что** блокирует;
- видит, **из каких слоев** складывается сила вещи;
- знает, **что останется навсегда**, что может сгореть, а что истечет по времени;
- может быстро менять комплект без повторной ручной сборки.

Kooperativ должен быть проще Apeha примерно в три раза по числу сущностей, но не беднее по числу осмысленных решений.

## 2. Тематический перевод в мир Kooperativ

| Apeha | Kooperativ | Смысл |
|---|---|---|
| Подкладка | Подкладка / броневкладыш | Второй слой под одеждой или броней |
| Камень | Деталь / модуль | Постоянная инженерная модификация |
| Заточка | Доработка | Последовательное рискованное усиление одного направления |
| Заклятие | Обработка | Временный химический или мастерской эффект |
| Свиток | Набор доработки / техкарта | Расходник для операции |
| Дом бойцов | Раздевалка / личный шкаф | Место подготовки комплекта |
| Маг | Спецмастерская | Установка временных и редких модификаций |
| Кузнец | Оружейник / механик | Постоянные модификации оружия и брони |
| Портной | Швейный цех | Подкладки, разгрузки, усиленная одежда |
| Оберег | Контрмера | Защита от крита, уворота, ответа, удачи |
| Минус оберега | Пробитие контрмеры | Подавление защиты противника |
| Комплект | Набор | Сохраненная раскладка экипировки и карманов |

Тон названий должен быть приземленным и узнаваемым:

- «стальная пластина»;
- «подшлемник»;
- «армированная подкладка»;
- «усиленная пружина»;
- «обмотанная рукоять»;
- «самодельный компенсатор»;
- «пропитка от порезов»;
- «антикоррозийная обработка».

Не использовать фэнтезийные камни, свитки, ману и зачарования в пользовательском тексте.

## 3. Матрица решений

### 3.1 Берем почти напрямую

| Решение Apeha | Решение Kooperativ |
|---|---|
| Выбор противника отдельно от выбора зон | Сохраняем |
| Удары на силуэте противника | Сохраняем |
| Блоки на своем силуэте | Сохраняем |
| 2 удара / 1 удар + 2 блока / 4 блока | Сохраняем как бюджет хода |
| Сначала выбрать клетку, потом подтвердить движение | Сохраняем |
| Подкладка зависит от внешнего предмета | Сохраняем |
| Подкладка имеет собственные статы и прочность | Сохраняем |
| Комплекты с кнопкой «Надеть» | Сохраняем |
| Модификации видны в названии и подробностях вещи | Сохраняем, но делаем понятнее |
| Операции с вещью только вне боя | Сохраняем |
| Вклад в бой виден в журнале и результате | Сохраняем |

### 3.2 Берем, но упрощаем

| В Apeha | В Kooperativ |
|---|---|
| До 19 подкладок | 4 вида подкладок на первом релизе |
| 12 основных и множество платных слотов | 8 базовых слотов без платного открытия |
| 2 обычных + 1 дополнительный камень | 1 постоянный модуль, позже второй для редких вещей |
| Несколько видов заклятий с независимыми сроками | 1 временная обработка на вещь |
| Бесконечная серия заточки | Максимум 5 уровней доработки |
| Полное сгорание всей серии при любом провале | Ступенчатый риск, без уничтожения базовой вещи |
| Отдельные профессии на каждый микроэтап | 3 понятные профессии: швейник, оружейник, механик |
| Комплекты подкладок и амуниции отдельно | Один набор хранит вещи, подкладки и карманы |
| Сложные обереги и минус-обереги | Существующие anti-dodge / anti-luck / anti-counter / anti-crit |
| Магия в бою | Отдельная кнопка «Карман», только разрешенные расходники |

### 3.3 Не берем

- преимущества аккаунта, влияющие на силу слотов;
- платное открытие базовых слотов;
- десятки профессий для камней и заклятий;
- фэнтезийные названия и ритуалы;
- бесконечный потолок усиления;
- уничтожение дорогого дополнительного модуля только из-за таймера;
- скрытые формулы предметов;
- необходимость вручную печатать полное название вещи при операции;
- зависимость базовых механик от премиум-аккаунта;
- 17–20 одновременно надетых предметов.

## 4. Боевая модель Kooperativ

### 4.1 Логика одного хода

Один ход должен читаться слева направо или сверху вниз:

1. **Цель**: выбран противник.
2. **Позиция**: текущая дистанция, доступные клетки.
3. **План**: выбран бюджет хода.
4. **Удары**: зоны на силуэте противника.
5. **Блоки**: зоны на своем силуэте.
6. **Проверка**: краткая строка «1 удар: голова · 2 блока: корпус, ноги».
7. **Подтверждение**: одна главная кнопка «Сделать ход».

Игрок не должен одновременно разбираться с клетками, карманами, журналом и зонами.

### 4.2 Desktop-композиция

```text
┌──────────── свой боец ──────────── поле ─────────── противник ────────────┐
│ HP, оружие, свои блоки       клетки и дистанция       HP, цель, удары    │
├────────────────────────────────────────────────────────────────────────────┤
│ 2 удара | 1 удар + 2 блока | 4 блока                                    │
│ План: удар в голову · блок корпуса · блок ног          [Сделать ход]     │
├────────────────────────────────────────────────────────────────────────────┤
│ [Карман 4] [Журнал]                                      таймер 07 сек   │
└────────────────────────────────────────────────────────────────────────────┘
```

Приоритеты:

- поле является крупнейшей областью;
- силуэты читаются как инструменты планирования, а не украшения;
- карманы и журнал свернуты по умолчанию;
- единственная визуально доминирующая кнопка — подтверждение хода.

### 4.3 Mobile-композиция

На телефоне не сжимать desktop. Использовать последовательные режимы:

1. поле и выбор цели;
2. нижняя панель плана;
3. по нажатию на стойку открывается лист с двумя силуэтами;
4. после заполнения лист закрывается и показывает краткий план;
5. отдельные кнопки «Карман» и «Журнал» открывают шторки.

Главная кнопка закреплена снизу, но не перекрывает поле.

### 4.4 Состояния

Обязательные состояния:

- цель не выбрана;
- цель вне досягаемости;
- движение выбрано, но не подтверждено;
- бюджет хода заполнен частично;
- бюджет заполнен полностью;
- действие отправляется;
- ожидание противника;
- ход завершен;
- бой завершен;
- потеря соединения и безопасное восстановление.

### 4.5 Цветовая грамматика

- красный: зона удара;
- зеленый: зона блока;
- янтарный: выбранное движение;
- синий: союзник;
- серый: недоступно;
- белый/бумажный: нейтральная информация.

Цвет всегда дублируется формой, иконкой и текстом.

### 4.6 Карманы

Оставить 4 подготовленных слота, но изменить визуальную роль:

- до боя игрок собирает карманы в снаряжении;
- в бою кнопка «Карман 4» открывает компактную ленту;
- пустые слоты не занимают постоянное место;
- предмет показывает эффект, остаток и доступность;
- использованный предмет исчезает/обновляется сразу;
- нельзя менять состав карманов во время боя.

## 5. Модель экипировки Kooperativ

### 5.1 Базовые слоты

Первый целевой набор:

1. голова;
2. корпус;
3. руки;
4. ноги;
5. обувь;
6. основная рука;
7. вторая рука;
8. аксессуар.

Карманы не входят в надетую амуницию, это отдельный боевой loadout.

### 5.2 Слои одного слота

```text
Слот тела
├── подкладка / броневкладыш (опционально)
└── основной предмет
    ├── распределение базового бюджета
    ├── доработка +0…+5
    ├── постоянный модуль 0…1
    └── временная обработка 0…1
```

Не смешивать эти источники в один JSON без типа. Игрок должен видеть происхождение каждого эффекта.

### 5.3 Подкладки первого релиза

Подкладки доступны только для:

- головы: подшлемник;
- корпуса: броневкладыш;
- рук: усиленные манжеты;
- ног: защитная подкладка.

Не создавать подкладки для оружия, колец, обуви и аксессуаров на первом релизе.

Правила:

- подкладка надевается в свой слой слота;
- внешний предмет можно носить без подкладки;
- подкладка без внешнего предмета не участвует в бою;
- перед началом боя система явно предупреждает и снимает неподдержанную подкладку;
- подкладка дает только зональную броню или одну контрмеру;
- подкладка имеет собственную прочность;
- при попадании износ делится между внешним предметом и подкладкой;
- сломанная подкладка перестает давать эффект, но не исчезает;
- подкладка чинится теми же ремонтными ресурсами, что ее материал.

### 5.4 Материалы подкладок

Вместо животных Apeha использовать материалы мира Kooperativ:

| Материал | Роль | Эффект |
|---|---|---|
| Ветошь | дешевый старт | малая прочность, небольшая броня |
| Войлок | защита от удара | броня и anti-counter |
| Резина | гибкая защита | anti-crit / anti-dodge по типу слота |
| Стальная пластина | тяжелый верх | высокая броня, штраф веса |

Одна подкладка производится из трех партий материала. Смешанный рецепт разрешен позднее, после проверки баланса чистых материалов.

### 5.5 Доработка

Доработка заменяет бесконечную заточку Apeha.

- +1…+3: безопасные ступени, растут цена и расход деталей;
- +4: 75% успех, провал откатывает до +3;
- +5: 50% успех, провал откатывает до +3;
- базовая вещь никогда не уничтожается;
- направление выбирается один раз: урон, точность, броня, прочность или одна контрмера;
- смена направления требует полного сброса доработки;
- шанс, стоимость и последствия показываются до подтверждения.

Существующий `upgradeLevel` и `upgradeModifiersJson` можно мигрировать в эту модель без слома Stage 2.

### 5.6 Постоянные модули

Первый релиз: один модуль на вещь.

Примеры:

- оружие: усиленная пружина, рукоять, прицел, компенсатор;
- броня: пластина, усиленный шов, жесткая вставка;
- аксессуар: скрытый карман, жетон, аптечный подсумок.

Модуль:

- существует отдельным предметом до установки;
- после установки принадлежит конкретной вещи;
- снимается мастером с риском повреждения модуля, но не базовой вещи;
- дает один главный эффект и максимум один побочный;
- не имеет отдельной прочности в первом релизе.

### 5.7 Временная обработка

Одна обработка на вещь:

- антикоррозийная;
- противоударная пропитка;
- оружейная смазка;
- временная пристрелка.

Правила:

- длится 3, 7 или 14 дней;
- не уничтожает модуль после окончания;
- эффект просто выключается;
- продление доступно за 24 часа до конца;
- таймер виден на вещи и в наборе;
- обработка не участвует в рыночной цене автоматически.

### 5.8 Наборы

Игрок получает 3 бесплатных набора:

- «На работу»;
- «В бой»;
- «На турнир» или пользовательское имя.

Набор хранит:

- основные вещи;
- подкладки;
- карманы;
- выбранное оружие.

Нажатие «Надеть» выполняет атомарную проверку:

- предметы существуют и принадлежат игроку;
- не сломаны;
- требования выполнены;
- игрок не в бою и не на смене;
- нет конфликтующих слотов.

Если часть набора недоступна, показать список проблем и не оставлять персонажа в полусобранном состоянии.

## 6. Карточка вещи

### 6.1 Свернутая строка

```text
[картинка] Бронежилет «Кооператор» +3
Корпус · редкий · 72/100
+18 броня · anti-crit 8%
[подкладка] [модуль] [обработка 2д 14ч]
```

### 6.2 Раскрытие

Разделы:

1. базовые свойства;
2. распределенный бюджет;
3. доработка;
4. модуль;
5. обработка и срок;
6. подкладка;
7. требования;
8. прочность и стоимость ремонта;
9. история операций.

Итоговые числа показываются сверху, происхождение каждого числа ниже.

### 6.3 Маркеры

Вместо `(мод)(закл)(доп)`:

- `+3` — доработка;
- `М` — установлен модуль;
- `П` — надета подкладка;
- `⏱` — активна обработка;
- `!` — сломано или скоро истечет.

У маркера всегда есть понятная подпись/tooltip.

## 7. Производственная интеграция Stage 3

### 7.1 Первый вертикальный срез

Согласовать с существующим handoff:

`scrap -> steel/component -> TT pistol -> battle wear -> repair component`

Добавить минимальную параллельную ветку:

`ветошь + резина + стальная пластина -> броневкладыш корпуса -> боевой износ -> ремонт`

Это проверяет сразу:

- рецепты;
- объектные склады;
- профессию;
- производство уникального предмета;
- двухслойную экипировку;
- зональный бой;
- износ и ремонт;
- рынок.

### 7.2 Профессии первого среза

- оружейник: пистолет и постоянный оружейный модуль;
- швейник: подкладки;
- механик: ремонт, броневставки и модули.

Не вводить отдельного огранщика, заклинателя и мастера каждого модуля.

## 8. Схема данных

### 8.1 Не перегружать ItemInstance

Добавить отдельные сущности:

```text
ItemAttachment
- id
- hostItemId
- attachmentItemId
- kind: LINING | MODULE
- slotCode
- installedAt
- installedByCharacterId
- metadata

ItemTreatment
- id
- itemId
- treatmentCode
- effectJson
- startsAt
- expiresAt
- appliedByCharacterId
- status

EquipmentLoadout
- id
- characterId
- name
- position

EquipmentLoadoutEntry
- loadoutId
- itemId
- layer: BASE | LINING | POCKET
- slotCode
- position
```

Доработку нормализовать из текущего `upgradeModifiersJson` в читаемую структуру при Stage 3 migration, сохранив старое поле на переходный период.

### 8.2 Инварианты

- одна базовая вещь на слой `BASE` одного слота;
- одна подкладка на слой `LINING` одного слота;
- один модуль на вещь в первом релизе;
- одна активная обработка на вещь;
- attachment не может быть установлен в две вещи;
- проданная/выброшенная вещь не может остаться в наборе;
- сломанная вещь не надевается набором;
- все операции логируются с correlation ID;
- проверка набора и смена экипировки выполняются транзакционно.

## 10. Порядок реализации

### Фаза A. Боевая визуальная композиция

Без изменения формул:

1. два силуэта;
2. раздельные зоны ударов и блоков;
3. строка плана;
4. один confirm CTA;
5. карманы и журнал в раскрываемых панелях;
6. desktop/mobile responsive states;
7. визуальные regression screenshots.

### Фаза B. Читаемая карточка текущей вещи

На существующих данных:

1. итоговые статы;
2. базовое распределение;
3. текущий upgrade;
4. прочность;
5. требования;
6. происхождение;
7. история текущих ItemLog.

### Фаза C. Подкладка первого среза

1. schema и API;
2. только корпус;
3. один броневкладыш;
4. установка/снятие;
5. equipment snapshot;
6. зональный эффект;
7. совместный износ;
8. ремонт;
9. рынок;
10. симуляция.

### Фаза D. Модули и доработка +0…+5

1. нормализованная модель;
2. один модуль;
3. риск +4/+5;
4. preview before commit;
5. история;
6. audit и anti-replay.

### Фаза E. Наборы

1. сохранить;
2. переименовать;
3. проверить;
4. атомарно надеть;
5. показать конфликт;
6. mobile selector.

### Фаза F. Временные обработки

Только после стабильного баланса постоянных модулей.

## 11. Что делать сейчас, а что позже

### Только Stage 3

- новые рецепты и профессии;
- постоянные модули как отдельные предметы;
- атомарные серверные наборы;
- совместный износ;
- временные обработки;
- рынок модифицированных вещей.

## 12. Балансовые ограничения

- Подкладка не дает больше 25% силы внешней вещи того же тира.
- Модуль не дает больше 15% силы внешней вещи.
- Обработка не дает больше 10% и всегда временная.
- Доработка +5 не должна увеличивать суммарную эффективность вещи более чем на 30%.
- Все слои вместе не должны давать вещи более 60% сверху базовой силы.
- Вес подкладки и модуля учитывается.
- Каждая контрмера имеет cap в `BalanceConfig`.
- Любое изменение проходит детерминированную боевую матрицу и экономическую симуляцию.

## 13. Acceptance criteria

### Бой

- игрок за 3 секунды различает цель, удары и блоки;
- невозможно подтвердить переполненный бюджет;
- движение и атака визуально различаются;
- план хода читается одной строкой;
- на mobile нет постоянной боковой колонки;
- восстановление страницы возвращает актуальный ход.

### Экипировка

- игрок видит итог и происхождение каждого бонуса;
- подкладка не работает без внешней вещи;
- сломанные слои явно показаны;
- набор либо надевается целиком, либо не меняет ничего;
- таймер обработки виден до подтверждения покупки/продления;
- рынок показывает все постоянные свойства до покупки;
- боевой snapshot воспроизводим по логам.

## 14. Рекомендация

Начать не с подкладок, а с **Фазы A: визуальная композиция боя**. Она использует уже корректный canonical resolver и немедленно улучшает читаемость без миграций и балансового риска.

После нее сделать **Фазу B: карточку вещи**. Только когда игроку понятно, откуда берутся параметры, вводить один корпусной броневкладыш как первый реальный вертикальный срез Stage 3.
