# Отчёт репетиции миграций Этапа 2

Основание: MASTER ТЗ Этап 2 v2.2, раздел 41.3; ревизия 2.3, раздел 4.

Репетиция выполняется на **копии прод-БД**, а не на чистой. Смысл — поймать то,
что проявляется только на живых данных: нарушенные ограничения, длинные
блокировки, неожиданные NULL в старых строках.

## 1. Процедура

```bash
# 1. Дамп прода
ssh vps-game "cd /opt/mmo90s && docker compose -f docker-compose.prod.yml \
  -f docker-compose.vps.yml exec -T postgres pg_dump -U mmo90s mmo90s" > /tmp/prod-copy.sql

# 2. Отдельная база под репетицию
docker run -d --name mmo90s-rehearsal -e POSTGRES_PASSWORD=x \
  -e POSTGRES_DB=mmo90s -p 55432:5432 postgres:16

# 3. Заливка копии
psql "postgres://postgres:x@127.0.0.1:55432/mmo90s" < /tmp/prod-copy.sql

# 4. Применение миграций с замером
time DATABASE_URL="postgres://postgres:x@127.0.0.1:55432/mmo90s" npx prisma migrate deploy

# 5. Сид дважды — проверка идемпотентности
DATABASE_URL="..." npx tsx prisma/seed.ts
DATABASE_URL="..." npx tsx prisma/seed.ts

# 6. Уборка
docker rm -f mmo90s-rehearsal && rm /tmp/prod-copy.sql
```

Дамп содержит персональные данные игроков: удалить сразу после репетиции,
в репозиторий не класть, наружу не передавать.
