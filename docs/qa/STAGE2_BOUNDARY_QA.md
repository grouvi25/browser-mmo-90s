## 2. Технические проверки (§39.3)

Результат каждой команды вставляется в протокол дословно.

### 2.1. Инварианты данных

```sql
-- 1. Отрицательных денег нет
SELECT count(*) FROM characters WHERE money < 0;
```
Ожидание: `0`. Факт: ______

```sql
-- 2. Инварианты ресурсных стеков
SELECT count(*) FROM resource_stacks
 WHERE amount < 0 OR reserved_amount < 0 OR reserved_amount > amount;
```
Ожидание: `0`. Факт: ______

```sql
-- 3. Предмет не задвоен в активных лотах
SELECT item_instance_id, count(*) FROM market_listings
 WHERE status = 'ACTIVE' AND item_instance_id IS NOT NULL
 GROUP BY 1 HAVING count(*) > 1;
```
Ожидание: пусто. Факт: ______

```sql
-- 4. У каждой денежной проводки корректный balanceAfter (выборка последних 50)
SELECT character_id, amount, balance_after, reason_code, created_at
  FROM currency_logs ORDER BY created_at DESC LIMIT 50;
```
Проверка вручную: цепочка `balance_after` монотонно продолжает предыдущую по
каждому персонажу. Вердикт: ______
