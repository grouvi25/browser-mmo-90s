# Этап 5 — антиабуз

Приложение к `MASTER_TZ_STAGE_5_FINAL_ASSEMBLY_RELEASE_PREP`.

Источник списка рисков — «Реестр механик по модулям», раздел 31.

---

# 1. Два класса мер, и почему их два

**Жёсткие лимиты** работают молча, всегда и для всех. Это не наказание, а
правила игры, и потому они **описываются игроку** в разделе ограничений первой
версии. Игрок, упёршийся в лимит, должен понимать, во что он упёрся.

**Сигналы** ничего не делают сами. Они попадают в раздел алертов админки с
объяснением, что показалось подозрительным, и админ решает.

Разделение принципиальное. Автоматический бан по эвристике на закрытом тесте с
десятками игроков поймает случайных, а не нарушителей: самые активные игроки
всегда выглядят как самые подозрительные. Это принцип П3 мастер-ТЗ.

# 2. Жёсткие лимиты

## 2.1. Полный список

```ts
antiAbuse: {
  botExpDailyShare:      0.40,   // доля дневного боевого опыта с ботов
  levelGapPenaltyStep:   0.15,   // за уровень разницы
  levelGapPenaltyFloor:  0.10,   // не ниже этого множителя
  repeatBattleShare:     0.25,   // опыт за повторный бой той же пары за сутки
  transferDailyCap:      50000,  // рублей одному аккаунту в сутки
  transferDailyCapItems: 5,      // предметов одному аккаунту в сутки
}
```

Ещё три жёстких лимита уже действуют — их ввёл Этап 4, и здесь они только
перечислены, чтобы список был полным:

```ts
strategy: {
  helper:        { dailyShiftCap: 6 },     // смен помощника в сутки
  objectAttack:  { cooldownHours: 72 },    // между атаками на один объект
  territory:     { claimClanCooldownHours: 24 },  // заявок бригады в сутки
}
```

Плюс два правила без числа: помощник работает только на объектах хозяина и
бригады, объект игрока вне бригады не атакуется вовсе.

## 2.2. Опыт с ботов

```
если дневной опыт с ботов >= 0.40 × дневного боевого опыта,
то дальнейшие бои с ботами дают 0 опыта
```

Боты нужны для обучения и для игры в мёртвые часы, а не как основной источник
прогресса. Порог в 40% оставляет их полезными и не даёт качаться только на них.

## 2.3. Разница уровней

```
множитель = max(0.10, 1 − 0.15 × |уровень1 − уровень2|)
```

| Разница | Множитель |
|---|---|
| 0 | 1.00 |
| 2 | 0.70 |
| 4 | 0.40 |
| 6 | 0.10 |
| 10+ | 0.10 |

Закрывает фарм опыта через слабых: бить новичка бесполезно уже с четвёртого
уровня разницы. Пол в 0.10, а не 0 — иначе высокоуровневые вообще перестанут
принимать вызовы от новичков, и новичкам не с кем будет играть.

## 2.4. Повторные бои

```
второй и последующие бои той же пары персонажей за сутки → 25% опыта
```

Основная мера против договорных боёв. Она же самая мягкая: друзья, которые
честно дерутся дважды, теряют немного, а пара, гоняющая двадцать боёв подряд,
не получает почти ничего.

## 2.5. Передачи

```
одному аккаунту в сутки: не более 50 000 ₽ и не более 5 предметов
```

Считается по всем каналам сразу: прямая передача, рынок, клановый склад,
общак. Иначе лимит обходится продажей себе лота по завышенной цене — самая
очевидная схема перелива.

Превышение — отказ, а не сигнал: перелив денег ломает экономику быстрее, чем
админ успеет отреагировать.

# 3. Сигналы

## 3.1. Модель

```prisma
enum AbuseSignalKind {
  MULTI_ACCOUNT
  MATCH_FIXING
  DUPLICATION
  BOT_FARMING
  WEAK_FARMING
  MONEY_FUNNEL
  CLAN_STORAGE_DRAIN
  MARKET_MANIPULATION
  AUTOCLICKER
}

enum AbuseSignalStatus {
  OPEN
  REVIEWED
  DISMISSED
}

model AbuseSignal {
  id        String            @id @default(uuid())
  kind      AbuseSignalKind
  status    AbuseSignalStatus @default(OPEN)
  severity  Int               // 1..3
  /** Кого касается. Аккаунтов может быть несколько — граф связей. */
  userIds   String[]          @map("user_ids")
  /** Человекочитаемое объяснение: что именно показалось подозрительным. */
  summary   String
  /** Числа, на которых сигнал сработал: для проверки и для отклонения. */
  evidence  Json
  reviewedByAdminId String?   @map("reviewed_by_admin_id")
  reviewedAt DateTime?        @map("reviewed_at")
  createdAt DateTime          @default(now()) @map("created_at")

  @@index([status, severity, createdAt])
  @@map("abuse_signals")
}
```

`summary` обязателен и пишется словами. Сигнал «подозрительная активность
у игрока X» бесполезен: админ не сможет ни проверить его, ни отклонить.
Сигнал «между X и Y за трое суток 14 боёв, все выиграл X, разница уровней 8»
проверяется за минуту.

`evidence` хранит числа, на которых сигнал сработал. Без них отклонённый
сигнал невозможно перепроверить, когда правило изменится.

## 3.2. Четырнадцать сигналов

| Сигнал | Условие срабатывания | Тяжесть |
|---|---|---|
| `MULTI_ACCOUNT` | два аккаунта с общим IP и хотя бы одной передачей между ними | 2 |
| `MATCH_FIXING` | пара персонажей, ≥ 10 боёв за 3 суток, ≥ 80% побед у одного | 2 |
| `DUPLICATION` | сумма экземпляров предмета не сходится с журналом создания | 3 |
| `BOT_FARMING` | ≥ 80% боевого опыта за неделю получено с ботов | 1 |
| `WEAK_FARMING` | ≥ 20 боёв за сутки с разницей уровней ≥ 5 | 1 |
| `MONEY_FUNNEL` | односторонний поток: ≥ 90% передач между парой в одну сторону, объём ≥ 100 000 ₽ | 2 |
| `CLAN_STORAGE_DRAIN` | вынос со склада клана ≥ 80% дневного лимита три дня подряд | 1 |
| `MARKET_MANIPULATION` | ≥ 5 сделок по краю ценового коридора между парой аккаунтов | 2 |
| `AUTOCLICKER` | ≥ 50 действий с разбросом интервалов < 2% | 2 |
| `HELPER_DRAIN` | ≥ 80% смен помощников игрока за неделю на клановых объектах, и он не главарь | 1 |
| `OBJECT_TRANSFER_TRAP` | владелец переведённого в бригаду объекта исключён из неё в течение 72 часов после перевода | 3 |
| `WAR_COLLUSION` | одна и та же пара бригад ≥ 4 заявок за 14 суток, районы возвращаются к прежним владельцам | 2 |
| `CLAIM_REFUNDED` | заявка погашена с возвратом взноса — событие редкое, показывается всегда | 1 |
| `ROBBERY_STREAK` | бригада вынесла из чужих объектов ≥ 40 000 ₽ за сутки | 1 |

Пять последних принёс Этап 4. Тяжесть 3 у `OBJECT_TRANSFER_TRAP` не случайна:
перевод объекта в бригаду необратим по замыслу (иначе бригада становится
отмывочной), и связка «переведи, потом выгоню» — единственный способ отнять у
игрока объект насовсем. Это не дисбаланс, а мошенничество между людьми, и
разбирать его должен человек.

`CLAIM_REFUNDED` — сигнал не о нарушении, а о редком событии. Возврат взноса
случается ровно в одном случае: к часу боя у нападающей стороны не осталось ни
одного бойца, то есть все они удалены. Само по себе это может быть и чисткой
мультиаккаунтов, и дефектом, и админ обязан увидеть каждый такой случай.

Чего в списке нет намеренно: сигнала на «убыточную» войну. Заявка стоит 20
авторитета, победа даёт 15, поэтому обмен районами между двумя бригадами
убыточен обеим — договорная война не окупается сама, и ловить нужно только
сговор ради защиты от третьих, чем и занят `WAR_COLLUSION`.

## 3.3. Граф связей

Единственный по-настоящему новый механизм этапа. Строится раз в сутки фоновой
задачей.

Вершины — аккаунты. Рёбра появляются при:

- совпадении IP за последние 30 суток;
- передаче денег или предметов любым каналом;
- участии в одном клане;
- сделке на рынке между аккаунтами.

Рёбра взвешены: общий IP весит больше, чем одна сделка на рынке. Сигнал
`MULTI_ACCOUNT` срабатывает не на голом совпадении IP — за одним IP сидит
общежитие, семья или интернет-кафе, и в игре 90-х это ожидаемо, — а на
совпадении **плюс** односторонний поток ценностей.

Граф хранится как рёбра, а не как готовые кластеры: правила кластеризации
будут меняться, а сырые связи останутся верными.

## 3.4. Обработка

```
GET  /api/admin/abuse/signals?status=&kind=&severity=&cursor=
→ 200 { items: [...], nextCursor }

POST /api/admin/abuse/signals/:id/review    Idempotency-Key
  { status: 'REVIEWED'|'DISMISSED', reason }
→ 200 { actionId }
```

Отклонение сигнала тоже требует причины и попадает в журнал админских
действий. Массово отклонённые сигналы одного вида — повод пересмотреть
правило, а не игрока.

# 4. Дюп: отдельно

Из девяти рисков дюп — единственный, который нельзя поймать эвристикой. Его
ловят сверкой.

```
для каждого шаблона предмета:
  число живых экземпляров
  == создано (крафт + магазин + дроп + админ) − удалено (продажа + поломка + админ)
```

Расхождение — сигнал тяжести 3 и повод остановить рынок до разбора.

Сверка запускается раз в сутки и после каждого выката. Второе важнее: дюп чаще
всего появляется не от действий игрока, а от гонки в новом коде.

Та же сверка применяется к авторитету клана (`ClanAuthorityLog` против
`Clan.authority`) и к общаку. Принцип один: **у каждой накопительной величины
есть журнал, и они обязаны сходиться**.

# 5. Капча

В реестре механик значится «капча при подозрении». Из разведки GanjaWars взято
прямое предупреждение: не копировать капчу как игровую механику.

Решение: капча только на **регистрации** и **восстановлении пароля**.
Внутри игрового цикла капчи нет нигде.

Капча посреди смены или боя наказывает честного игрока за то, что он играет
много, и при этом почти не мешает автоматизации: распознавание капчи — решённая
задача, а раздражение живого игрока — нет.

Против автокликеров работает сигнал `AUTOCLICKER` и разбор админом, а не
капча.

# 6. Что игроку рассказывают

В раздел «Ограничения первой версии» попадают все жёсткие лимиты дословно:

- бои с ботами дают не более 40% дневного боевого опыта;
- бой с сильно неравным противником даёт меньше опыта, вплоть до 10%;
- повторные бои с одним и тем же противником за сутки дают 25% опыта;
- одному игроку можно передать не более 50 000 ₽ и 5 предметов в сутки.

Скрытых лимитов не бывает: игрок, упёршийся в невидимую стену, считает игру
сломанной и уходит. Сигналы, наоборот, не публикуются — иначе они превращаются
в инструкцию, как их обойти.

Это единственное место документа, где что-то скрывается от игрока, и граница
проведена сознательно: **правила видны, детекторы нет**.
