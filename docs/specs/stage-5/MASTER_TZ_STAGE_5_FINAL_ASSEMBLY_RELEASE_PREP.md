# Часть I. Обзор и границы

## 1. Что такое Этап 5

Четыре предыдущих этапа строили механики. Этап 5 не добавляет игровых систем —
кроме одной, которую заказчик перенёс сюда сознательно (часть V). Он делает так,
чтобы построенным можно было управлять, доверять и пользоваться без
разработчика рядом.

Это единственный этап без игрового цикла. У него три пользователя, и ни один
из них не игрок:

| Кто | Что ему нужно |
|---|---|
| Администратор | видеть, что происходит, и уметь вмешаться, не заходя в базу |
| Владелец проекта | знать, что экономику не ломают, а если ломают — узнать первым |
| Новый разработчик | поднять проект и понять его, не спрашивая автора |

Результат по плану заказчика — «полноценная первая версия, готовая к закрытому
тестированию». Ключевое слово **закрытому**: игра впервые встречается с живыми
людьми, у которых нет причин играть честно.

## 2. Принципы этапа

**П1. Всё обратимо.** Любое административное действие записывает, как его
отменить. Админ, выдавший миллион, должен уметь забрать его одной кнопкой, а
не запросом в базу.

**П2. Ничего без причины.** Каждое админское действие требует текстовой
причины. Ручка без причины отвечает ошибкой, а не выполняет.

**П3. Антиабуз не наказывает сам.** Он собирает сигналы и показывает админу.
Автоматический бан по эвристике на закрытом тесте даст больше ложных
срабатываний, чем пойманных, и отпугнёт самых активных.

**П4. Непроверенный механизм считается неработающим.** Откат в CD написан и ни
разу не срабатывал по-настоящему. До релиза он проверяется фактическим
откатом на боевой копии.

**П5. Документация — часть поставки.** Не приложение к ней. Четыре документа
раздела 20 входят в приёмку наравне с кодом.

**П6. Приёмка исполняемая, а не бумажная.** Принцип новый, и он оплачен
Этапом 4. Там протокол из 22 проверок был написан текстом, все они выглядели
покрытыми тестами — а когда те же проверки прогнали скриптом на живой базе,
четыре упали, и три оказались настоящими дефектами. Один из них: бой за
территорию создавался строками в базе и не запускался — в него нельзя было
сделать ни одного хода. Ни один тест этого не ловил, потому что тесты
проверяли то, что автор считал важным, а приёмка проверяет то, что обещано
заказчику. Поэтому приёмка Этапа 5 — это `npm run accept:stage5`, скрипт с
кодом возврата, а не список для галочек.

## 8. Обратимость

Самое важное в этапе и самое недооценённое. Сегодня админ действует
безвозвратно: выдал миллион — миллион в экономике навсегда.

### 8.1. Журнал с обратной операцией

Каждое действие пишет в `AdminActionLog` не только что сделано, но и **как это
отменить**: тип обратной операции и её параметры. Откат — тоже действие и тоже
пишется в журнал, со ссылкой на отменяемое.

| Действие | Обратная операция |
|---|---|
| Выдать деньги | списать ту же сумму |
| Списать деньги | вернуть ту же сумму |
| Выдать предмет | удалить выданный экземпляр по id |
| Удалить предмет | восстановить из снимка полей |
| Бан | разбан |
| Заморозка рынка | разморозка |
| Правка справочника | вернуть прежнее значение из снимка |
| Выдать подписку | отозвать и вернуть прежний срок из снимка |
| Отозвать подписку | выдать прежний срок из снимка |
| Правка авторитета клана | обратная правка на ту же величину |
| Сброс района в ничейный | вернуть владельца, ступень и защиту из снимка |
| Гашение заявки с возвратом | **нет обратной операции — действие запрещено** |
| Снятие отката налёта | вернуть отметку времени атаки из снимка |

Последняя строка — пример правила, а не исключение из него: погашенная заявка
уже вернула взнос в общак и разблокировала район, за это время его мог занять
другой клан. Отменить такое нельзя, значит выдавать админу нельзя тоже.
Действие остаётся в списке как **гашение без возврата** — у него обратная
операция есть.

### 8.2. Цепочка транзакций

По любому предмету, сумме или персонажу — вся история перемещений одним
запросом, с общим correlation id по журналам денег, предметов, ресурсов,
производства, общака клана, авторитета и админских действий.

Это то, чем ловят дюп и перелив. Без цепочки журналы — просто много строк:
девять таблиц, в которых нельзя проследить один предмет.

### 8.3. Причина обязательна

Правило П2 в реализации: поле `reason`, минимум 10 символов, во всех мутирующих
админских ручках. Без причины — 422. Причина попадает в журнал и видна в
цепочке транзакций.

Две существующие ручки — выдача и отзыв премиума — причины сегодня не требуют.
Это долг Д4, и закрывается он здесь же, а не «когда-нибудь»: ручка без причины
делает правило необязательным для всех остальных.

## 9. Права админов

Роли уже есть в схеме: `AdminRole` = `SUPPORT`, `MODERATOR`, `SUPER_ADMIN`.
Новых значений не вводим — достраивается матрица прав поверх существующих трёх.

| Роль | Может |
|---|---|
| `SUPPORT` | только смотреть: списки, карточки, логи, цепочки транзакций |
| `MODERATOR` | всё выше плюс бан, разбан, завершение зависшего боя, жалобы, снятие отката налёта |
| `SUPER_ADMIN` | всё выше плюс деньги, предметы, заморозка рынка, справочники, premium, авторитет, сброс района, откат чужих действий |

Правка справочников, заморозка рынка и сброс района — только у высшей роли:
это действия, которые меняют игру для всех сразу.

Четвёртая роль («экономист» без права на справочники) при необходимости
добавляется аддитивно, отдельным `ALTER TYPE ... ADD VALUE`. Для закрытого
теста трёх достаточно: админов на нём единицы, и дробить права незачем.

Роль пишется в журнал вместе с действием. Действие под ролью, которой уже нет
у аккаунта, остаётся в истории с прежней ролью.

| Рыночные махинации | коридор цен есть, нужен алерт на сделки по краям | частично |
| Автокликеры | ритм действий: подозрительно ровные интервалы | нет |
| **Помощник доит общак бригады** | помощник допущен на клановые объекты, зарплату платит их баланс | лимит есть, сигнала нет |
| **Необратимый перевод объекта** | «переведи объект в бригаду, потом выгоню» | сигнала нет |
| **Договорная война за район** | две бригады обмениваются районами, держа защиту 48 ч против третьих | сигнала нет |
| **Гашение заявки с возвратом** | единственный путь возврата взноса; событие редкое и должно быть видно | сигнала нет |
| **Ограбление по кругу** | откат 72 часа на объект, но врагов у бригады может быть много | лимит есть, сигнала нет |

По пяти новым рискам важно сказать, чего делать **не надо**. Три из них уже
закрыты правилами Этапа 4 арифметически, и добавлять поверх них ограничения
значит чинить несуществующее:

- заявка стоит 20 авторитета, победа даёт 15, поэтому обмен районами между
  двумя бригадами убыточен обеим — договорная война не окупается сама по себе,
  и нужен только сигнал, чтобы видеть сговор ради защиты от третьих;
- взнос возвращается лишь тогда, когда к часу боя не осталось ни одного
  нападающего, а состав пустеет только удалением персонажей — дешёвой отменой
  это не станет, но каждое такое событие админ обязан видеть;
- помощник ограничен шестью сменами в сутки и работает только на объектах
  хозяина и бригады, поэтому «доение» упирается в баланс объекта, который
  пополняет сама бригада.

## 11. Два класса мер

Разделение принципиальное, потому что от него зависит, отпугнёт антиабуз
игроков или нет.

**Жёсткие лимиты** работают молча, всегда и для всех. Это не наказание, а
правила игры, и они **описываются игроку** в разделе ограничений первой версии.

Два из четырёх, которые версия 5.0 собиралась вводить, уже действовали с
Этапа 1: затухание опыта с ботов и коэффициент разницы уровней. Формулы
Этапа 5 предлагали другие числа — например, при разнице в четыре уровня 0.40
против действующих 0.90. Менять принятую боёвку под видом антиабуза мы не
стали: цель у правил одна, а второе правило поверх первого — это правка
баланса, и она должна называться правкой баланса.

Лимит передач пришлось переопределить: **прямых передач денег в игре нет**.
Единственный канал движения денег между аккаунтами — рынок, и самая очевидная
схема перелива это продать себе лот по завышенной цене. Поэтому лимит считает
поток пары через рынок, а не через несуществующую ручку «передать деньги».

| Лимит | Значение | Состояние |
|---|---|---|
| Суточный опыт с ботов | затухание 5% за бой, пол 0.1 | **уже есть**, Этап 1 |
| Коэффициент разницы уровней | таблица `battleExp.levelDiffCoeff`, ноль при разнице от 15 | **уже есть**, Этап 1 |
| Поток ценностей между парой | 50 000 ₽ и 5 предметов в сутки | **сделано 04.09.2026** |
| Повторный бой с той же парой | второй и далее за сутки дают 25% опыта | **сделано 04.09.2026** |
| Смены помощника | 6 в сутки, только свои и бригадные объекты | **уже есть**, Этап 4 |
| Откат налёта на объект | 72 часа | **уже есть**, Этап 4 |
| Заявка бригады на район | одна в сутки | **уже есть**, Этап 4 |

**Сигналы** ничего не делают сами. Они попадают в раздел алертов админки с
объяснением, что именно показалось подозрительным, и админ решает.

Это правило П3. Автоматический бан на закрытом тесте с десятками игроков
поймает случайных, а не нарушителей.

## 12. Капча

В реестре механик есть «капча при подозрении». Из разведки GanjaWars взято
прямое предупреждение: не копировать капчу как игровую механику.

Предложение: капча **только на регистрации и восстановлении пароля**, никогда
внутри игрового цикла. Капча посреди смены или боя наказывает честного игрока
за то, что он играет много.

# Часть IV. Баланс

## 13. Сквозной прогон

Пять симуляторов есть, но каждый проверяет свой этап в отдельности. Никто не
проверял, что территории Этапа 4 не ломают коридоры Этапа 2.

Добавляется `scripts/simulate-full.ts`: один виртуальный месяц, в котором
одновременно живут боец, рабочий, владелец объекта, фермер, бармен, подписчик
с помощниками и бригада с территорией. Все механики четырёх этапов включены.

Отдельная задача прогона — свести расхождение, которое уже видно на бумаге:
мастер-ТЗ Этапа 3 называет коридор дневного дохода 700–900 ₽, а действующий
`simulate-economy.ts` проверяет 400–700 ₽ по валовому доходу. Одна из двух
цифр неверна либо считает другое; выяснить это надо до релиза, а не после.

## 14. Коридоры

Все определены в предыдущих этапах; здесь они проверяются **вместе**. Колонка
«чем проверен» добавлена в версии 5.1: без неё таблица выглядела как отчёт, а
была списком намерений.

| Что | Коридор | Откуда | Чем проверен сегодня |
|---|---|---|---|
| Доход дня активного игрока | 700–900 ₽ | Этап 3 | `simulate-economy` (другим числом, см. раздел 13) |
| Доход владельца объекта за час | 120–160% от смены | Этап 3 | `simulate-economy` |
| Доход фермы за час внимания | 60–80% от смены | Этап 3 | не проверен |
| Окупаемость объектов | 12–20 дней, бар 18–25 | Этап 3 | не проверен |
| Доля дохода от клана | ≤ 25% | Этап 3 | не проверен |
| Доля дохода от территории | ≤ 15% | Этап 4 | косвенно, `simulate-war` |
| Подписчик против активного игрока | ≤ 130% | Этап 4 | приёмка Этапа 4, факт 118.2% |
| Пьяный против равного трезвого | ≤ 52% побед | Этап 3 | `simulate-balance` |
| Доход от войны против дохода от работы | война ниже | Этап 4 | `simulate-war`, вердикт `warCheaperThanWork` |

Четыре коридора из девяти не проверены ничем. Это и есть содержание шага G4:
не «прогнать симулятор», а закрыть эти четыре строки.

Два последних коридора — самые важные, и оба про одно: **выгодная альтернатива
работе убивает работу**. Если пить или грабить выгоднее, чем производить, вся
экономика четырёх этапов схлопывается в одну стратегию.

## 15. Антимастерство

Отдельная проверка, которой не было ни разу. Структура `20/1–20/20` заложена в
Этапе 1 и не проверялась на длинной дистанции.

Вопрос, на который отвечает прогон: доходит ли игрок, качавший один тип оружия
20 уровней, до состояния, когда противник с антимастерством против этого типа
выигрывает у него автоматически. Если доходит — специализация наказывается, и
это надо чинить до релиза, а не после.

Проверка стала актуальнее с 03.09.2026: до этой даты командный бой не начислял
опыт оружия вовсе, и войны за район не двигали навык ни на шаг. Теперь двигают,
а значит и перелив в антимастерство на потолке 20 работает в них тоже.

# Часть V. Ревизия экономики

## 16. Импортный инструмент

Единственная содержательная механика этапа. Попала сюда решением заказчика от
03.09.2026 (вопрос В9 Этапа 4): открывать заново принятый Этап 3 ради неё
дороже, чем довезти отдельным пунктом здесь.

**Вторая ступень профессии закрывать не нужно.** База знаний писалась до
Этапа 3, а он развёл профессии на три передела в каждой из трёх веток
(`scrap_collector → foundry_worker → gunsmith` и две такие же), и допуск на
объект проверяется по предыдущему переделу. Вторая ступень — это ровно то, что
уже работает; заводить поверх неё ещё один уровень значило бы удваивать
сущность.

Остаётся импортный инструмент. Предложение:

| Свойство | Значение | Почему так |
|---|---|---|
| Ступень | 4-я, поверх трёх существующих | ступени инструмента уже есть, четвёртая ложится без новых правил |
| Где берётся | только рынок игроков и частные лавки | «импортный» значит редкий; государство его не продаёт |
| Откуда берётся | крафт из компонента верхнего передела | иначе это просто дорогая покупка, а не цель производства |
| Ресурс использования | 50 применений, как у прочих | менять расходник ради одной ступени незачем |
| Эффект | скорость цикла +15% сверх третьей ступени | тот же шаг, что между существующими ступенями |

Подтвердить на шаге G0: цену, компонент и то, что эффект — именно скорость, а
не качество выхода. Если заказчик хочет качество — это отдельный коридор
баланса и +2 дня.

## 18. Фактическая проверка отката

Правило П4 в работе. Откат в CD написан и ни разу не срабатывал.

Порядок проверки на боевой копии, не на проде:

1. поднять копию прода из снимка;
2. выкатить заведомо ломающую сборку (например, с падающей миграцией);
3. убедиться, что CD **сам** откатился и health зелёный;
4. сверить данные с исходным снимком;
5. записать результат в протокол релиза.

Пока этот пункт не пройден, релиз не считается готовым, даже если всё
остальное сделано.

## 21. Инструкция запуска

Проверяется буквально: новый человек на чистой машине по этому документу
поднимает проект и доходит до боя. Если где-то он спросил автора — документ

Отдельно фиксируется локальный стенд без Docker (`D:\work2\devstack` в текущей
рабочей среде): портативные PostgreSQL и Redis, скрипты запуска. Это не

Тестовая база выносится в документ отдельным абзацем: интеграционные тесты и
исполняемая приёмка чистят базу целиком, и путать их с рабочей нельзя.
Переменная `TEST_DATABASE_URL` и команда `npm run test:db:setup` — часть
инструкции, а не устное знание.

## 22. Инструкция администратора

Главное в ней — не перечень кнопок, а **чего делать нельзя** и почему:

- не править деньги без причины: причина уходит в журнал и в цепочку;
- не удалять предметы вместо отката операции;
- не менять справочники на живом проде без снимка;
- не банить по одному сигналу антиабуза;
- не сбрасывать район, пока по нему идёт бой: заявка останется без района.

следующей версии. Собирается из разделов «что не входит» всех пяти этапов и из
решений заказчика.

# Часть VIII. Приёмка и работы

## 24. Обязательные проверки

Сборка не принимается, пока не пройдены все. Проверки исполняются скриптом
`npm run accept:stage5` по образцу Этапа 4: база поднимается заново перед
каждой, проверка идёт через те же сервисы, что и приложение, отказы сверяются
по коду ошибки. Код возврата 1 при любом FAIL, отчёт в
`docs/stage5-acceptance-report.json`.

**Долги Этапа 4**
1. Каждый товар витрины выдаёт свой эффект; отложенные не выдаются даже админом.
2. Бой за территорию проходится до конца: 5×5, победитель получает район.

**Админка**
3. Каждое мутирующее действие требует причину от 10 символов, включая выдачу и отзыв премиума.
4. Каждое действие имеет записанную обратную операцию.
5. Откат возвращает состояние и сам пишется в журнал.
6. Действие без обратной операции недоступно ни одной роли.
7. Цепочка транзакций по предмету показывает всю историю, включая админские.
8. Цепочка по клану показывает общак, авторитет и налёты одной лентой.
9. `SUPPORT` не может выполнить ни одну мутацию.
10. Справочники, заморозка рынка и сброс района недоступны ниже `SUPER_ADMIN`.

**Антиабуз**
11. Опыт с ботов ограничен 40% дневного.
12. Бой с разницей уровней 10 даёт не более 10% опыта.
13. Повторный бой той же пары за сутки даёт 25% опыта.
14. Передача свыше 50 000 ₽ в сутки одному аккаунту отклоняется.
15. Сигналы попадают в алерты и **никого не банят**.
16. Капчи нет нигде, кроме регистрации и восстановления пароля.
17. Пять сигналов Этапа 4 срабатывают на подготовленных сценариях.

**Баланс**
18. Сквозной симулятор проходит все девять коридоров, включая четыре сегодня непроверенных.
19. Антимастерство не делает специализацию проигрышной.

**Релиз**
20. Откат CD проверен фактическим откатом на боевой копии.
21. Полный прогон протоколов зелёный, включая `accept:stage4`.
22. Снимок базы с меткой релиза существует и восстанавливается.

**Документация**
23. Новый человек поднимает проект по инструкции без вопросов автору.
24. Все четыре документа существуют и актуальны на дату релиза.
