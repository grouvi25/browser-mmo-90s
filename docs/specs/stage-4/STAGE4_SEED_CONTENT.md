# Этап 4 — содержимое сида

Приложение к `MASTER_TZ_STAGE_4_STRATEGY_PREMIUM_WAR`.

Правило Этапа 2, обязательное здесь: сид-таблицы живут в
`backend/prisma/economy-data.ts`, **не в `src/`**. Рантайм-образ не содержит
`src/`, и сид на выкате упадёт.

Весь сид этапа идемпотентен: повторный прогон не создаёт дублей и не сбрасывает
игровое состояние. Территория, у которой уже есть владелец, при повторном сиде
сохраняет владельца, долг и защиту — обновляются только имя и бонус.

---

# 1. Территории

Шесть строк, по числу районов в макете города. Коды дословно совпадают с
ключами `MENU.districts` во фронте и с `OBJECT_DISTRICTS` в этом же файле.

```ts
export const TERRITORIES = [
  { code: 'center',     name: 'Центр',           bonusCode: 'BATTLE_EXP',   bonusValue: 0.10 },
  { code: 'market',     name: 'Рынок',           bonusCode: 'MARKET_SHARE', bonusValue: 0.30 },
  { code: 'industrial', name: 'Промзона',        bonusCode: 'CYCLE_SPEED',  bonusValue: 0.15 },
  { code: 'station',    name: 'Вокзал',          bonusCode: 'STORAGE_CAP',  bonusValue: 0.10 },
  { code: 'garages',    name: 'Гаражи',          bonusCode: 'REPAIR_COST',  bonusValue: 0.20 },
  { code: 'suburb',     name: 'Спальный район',  bonusCode: 'UPKEEP_COST',  bonusValue: 0.25 },
] as const
```

Все шесть создаются в статусе `NEUTRAL`. Карта на старте пустая: раздавать
районы кланам при выкате нечестно, а оставлять часть районов невзятыми
навсегда — значит отрезать часть контента.

## 1.1. Значения бонусов

| `bonusCode` | Где применяется | Формула |
|---|---|---|
| `BATTLE_EXP` | начисление боевого опыта участнику клана | `exp × (1 + value)` |
| `MARKET_SHARE` | комиссия рынка со сделок в районе | `commission × value` в общак |
| `CYCLE_SPEED` | длительность цикла на объекте клана | `cycleMinutes × (1 − value)` |
| `STORAGE_CAP` | вместимость склада объекта клана | `storageCapacity × (1 + value)` |
| `REPAIR_COST` | стоимость ремонта предмета участнику | `cost × (1 − value)` |
| `UPKEEP_COST` | содержание клана и его территорий | `upkeep × (1 − value)` |

`bonusCode` разбирается сервисом по закрытому списку. Неизвестный код — ошибка
сида, а не игнорируемое значение: молча не применившийся бонус нашли бы через
неделю после выката.

## 1.2. Привязка объектов

Уже сделана шагом F0, здесь приведена для полноты. Источник —
`OBJECT_DISTRICTS` в том же файле, пишется в `ProductionObject.locationId`.

| Район | Объектов | Какие |
|---|---|---|
| `center` | 2 | Аптека, Швейный цех |
| `market` | 2 | Грузчик на рынке, Приёмка трав |
| `industrial` | 4 | Пункт металлолома, Малый завод, Фабрика деталей, Химлаборатория |
| `station` | 2 | Склад у вокзала, Пивная «У вокзала» |
| `garages` | 1 | Гаражный цех |
| `suburb` | 3 | Колхоз «Заря», Пилорама, Стройка кооператива |

Раскладка закреплена тестами с обеих сторон: `backend/src/tests/unit/districts`
проверяет полноту и распределение, спека `stage2.visual` — что коды районов во
фронте не разъехались с бэкендом.

## 2.1. Почему «ускорение цикла» — это время, а не сила

`CYCLE_INSTANT` закрывает **календарное время** цикла, но не набранный труд.
Труд по-прежнему набирается сменами живых игроков или помощников. Подписчик не
получает продукт из воздуха — он получает его раньше, при тех же затратах
труда. Ровно то, за что премиум и должен брать деньги.

Если бы товар закрывал и труд, он бы производил предметы за рубли — а это
прямое нарушение принципа П4 и удар по всей экономике Этапа 3.

## 2.2. Чего в витрине нет и не будет

- предметов с бюджетом статов любого размера;
- ресурсов и деталей;
- денег, авторитета, опыта;
- доступа к рецептам и объектам;
- территорий и всего, что с ними связано;
- влияния на бой любым способом.

Список приведён не для полноты, а как рабочее правило при добавлении товаров:
если новый товар попадает хоть в одну строку, его нельзя заводить.

# 3. Права клана

Право одно: `OBJECTS` в Этапе 3 уже есть, дублировать его незачем.

```ts
// добавляется в union ClanPermission (clans.formulas.ts)
//   ... | 'OBJECTS' | 'EDIT' | 'WAR'

// добавляется к правам существующих ролей, ничего не отбирая
export const CLAN_ROLE_GRANTS_STAGE4: Record<string, string[]> = {
  boss:      ['WAR'],
  brigadier: ['WAR'],
  fighter:   [],
  infantry:  [],
}
```

Коды ролей — существующие: `boss`, `brigadier`, `fighter`, `infantry`
(`DEFAULT_ROLES` в `clans.formulas.ts`), а не выдуманные `leader` и прочие.

Миграция прав аддитивна: существующим ролям права **добавляются**, ничего не
отбирается. Клан, где главарь уже перенастроил роли под себя, не должен
получить сюрприз при выкате.

# 4. Помощники

Профессии помощника — те же, что у игрока; отдельного справочника нет.
Ограничение одно: потолок уровня 3, поэтому верхние переделы помощнику
недоступны.

| Профессия | Доступна помощнику | Почему |
|---|---|---|
| `scrap_collector` | да | входной передел |
| `supplier` | да | входной передел |
| `procurer` | да | входной передел |
| `foundry_worker` | да | второй передел, требует уровень 0 |
| `carpenter` | да | второй передел |
| `pharmacist` | да | второй передел |
| `gunsmith` | до уровня 3 | верхние рецепты требуют 2–3 |
| `chemist` | до уровня 3 | то же |
| `cooperative_builder` | до уровня 3 | то же |

Формально помощник может встать на любой объект, чьё требование он покрывает.
Практически потолок 3 закрывает ему сборку ТТ (`requiredProfessionLevel: 2`,
но `requiredToolTier: 3`) и куртки — то есть всё, ради чего цепочка строилась.

# 5. Порядок сида

Территории сеются **после** производственных объектов: связь идёт от объекта к
району через `locationId`, и проверка «в районе есть объекты» должна работать
сразу после первого прогона.

```
1. ресурсы, объекты, рецепты          (Этапы 2–3, без изменений)
2. локации объектов                   (F0, уже в сиде)
3. территории                         (F1)
4. права клана                        (F4)
5. премиум-витрина                    (F5)
```

Пункт 4 идёт после территорий, потому что дефолтные права ролей ссылаются на
военные операции, которых без территорий не существует.

---

# 6. Что проверяет сид

Прогон сида на пустой базе и на боевой копии обязан дать одинаковый результат
по этим пунктам:

1. шесть территорий, все `NEUTRAL` на пустой базе;
2. на боевой копии владельцы, долги и защита сохранены;
3. у каждой территории известный `bonusCode`;
4. в каждом районе хотя бы один объект;
5. ни один товар витрины не выдаёт предмет со статами;
6. существующие роли кланов получили новые права, старые не потеряли.

Пункты 2 и 6 — единственные, которые нельзя проверить на пустой базе, и потому
именно они попадают в репетицию миграций перед выкатом.
